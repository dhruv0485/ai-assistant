## Application architecture
- Content pages use TanStack file routes; HR uses an Outlet parent with an index leaf so applicant and creation pages mount independently.
- Shared frontend session state lives in TribeProvider; this UI preview uses sample jobs and in-memory applications, never simulated successful authentication or message delivery.
- Document extraction is browser-only through dynamic PDF.js and Mammoth imports, keeping document contents in the active session.
- Reusable semantic styles live in src/styles.css and controls use the shared Button variants for consistent institutional styling.
- Shared metadata is generated by pageHead, while each content route supplies its own title, description, and any meaningful absolute cover image.
- The decorative home pipeline is an isolated SVG component using one shared browser animation clock and semantic CSS tokens, keeping its demonstration separate from actual scoring logic.
- The calculation walkthrough is an isolated frontend presentation with viewport-gated stage playback, manual navigation and reduced-motion support; its architecture examples never drive candidate scoring or claim connected services.
